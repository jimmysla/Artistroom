# AGENTS.md

## Overview
Artistroom is a German-language event registration SPA with a protected admin dashboard, deployed on Netlify.

## Architecture
- **Frontend**: Vite + React 19 + TypeScript SPA (`src/`). Routes: `/` (registration), `/login` and `/dashboard` (both `AdminPage`, which redirects to the right one by session state; old `/admin` → `/dashboard`). User-facing copy says „Login“ / „Dashboard“, never „Admin“. SPA fallback redirect in `netlify.toml`.
- **API**: Netlify Functions with custom `config.path` under `/api/*`:
  - `netlify/functions/register.mts` – `POST /api/registrations` (public; server-side validation, honeypot `website` field, one registration per e-mail address via `email_hash`).
  - `netlify/functions/admin-auth.mts` – `/api/admin/login|logout|session`.
  - `netlify/functions/transport-key.mts` – `GET /api/transport-key` (public; RSA key + challenge for `secure.ts`).
  - `netlify/functions/admin-places.mts` – `GET /api/admin/places?q=&session=` address suggestions for `LocationField`: Google Places API (New) with `GOOGLE_MAPS_API_KEY`, else Photon/OpenStreetMap (`source` in response). No map preview.
  - `netlify/functions/mail-images.mts` – images for mail templates in Netlify Blobs store `mail-images` (PNG/JPEG/GIF/WebP by magic bytes, ≤3 MB, never SVG): admin list/upload (sealed base64)/delete, public `GET /api/mail-images/:id` for mail clients.
  - `netlify/functions/payments.mts` / `payments-reconcile.mts` – public payment page API and 10-min reconciliation (see payments below).
  - `netlify/functions/survey.mts` (public `GET|POST /api/survey`, token per guest), `admin-survey.mts` (`GET /api/admin/survey/results` permission `umfrage`, `POST /api/admin/survey/send`), `survey-send.mts` (every 15 min, sends when `sendAt` (Berlin) passed).
  - `netlify/functions/audit-log-cleanup.mts` – scheduled daily, deletes log entries older than `LOG_RETENTION_DAYS` (90); `admin-logs` GET also prunes.
  - `netlify/functions/event-settings.mts` – `GET /api/event` (public subset incl. `ticketPrice`), `GET|PUT /api/admin/settings`, `POST /api/admin/settings/test-mail`. The SMTP password is never returned (`smtpPasswordSet` flag instead); empty = keep, `smtpPasswordClear: true` = remove.
  - `netlify/functions/admin-registrations.mts` – `GET /api/admin/registrations` (`?format=csv` for export), `GET|PATCH|DELETE /api/admin/registrations/:id`, `POST /api/admin/registrations/reset` (super only; sealed body with `confirm` = `RESET_CONFIRMATION` **plus `username`/`password` of a super user** – re-authenticated via `checkCredentials`; snapshots all rows into the log for undo, then `TRUNCATE … RESTART IDENTITY`).
  - `netlify/functions/admin-users.mts` – `/api/admin/users[/:id]` account management (super only; keeps ≥1 active super user, no self-delete/deactivate).
  - `netlify/functions/admin-logs.mts` – `GET /api/admin/logs` audit log with server-side filters (`action`, `user` (`-` = public), `from`/`to` Berlin days, `q`), max 1000 rows; `POST /api/admin/logs/:id/undo` (`{ notify }`).
- **Auth** (`netlify/lib/auth.ts`): admin accounts in DB table `admin_users` (scrypt hashes `scrypt$N$r$p$salt$hash`; initial `AdminArtist` seeded by a custom migration). Login sets an HMAC-signed, HttpOnly, SameSite=Strict cookie scoped to `Path=/api/admin` (8h TTL), signed with `SESSION_SECRET` if set, else the user's password hash. Every admin function calls `requireAdmin(req, ...permissions)` first, which returns the identity or an error Response (401/403). Password hashes (and the SMTP password) are AES-256-GCM encrypted at rest via `netlify/lib/crypto.ts` (`seal`/`open`, format `enc$v1$iv$tag$ct`). Key: `PASSWORD_ENCRYPTION_KEY` (≥32 chars) if set, else an auto-generated key in table `app_secrets`; `open` tries both, and hashes not sealed with the current key are re-sealed on the next successful login. Never change or lose an env key once set.
- **Transport encryption**: request bodies with passwords, login or personal data are sent fully encrypted, any length. `src/lib/api.ts` `sealedRequest()` → `secure.ts` `seal()` fetches `/api/transport-key` (RSA public key + HMAC-signed challenge, 5 min TTL), encrypts the whole JSON body with AES-GCM (key wrapped with RSA-OAEP) and sends `{ sealed }`; the server reads it with `readSealed(req)` (throws `TransportError` → 400; plain bodies are rejected). Used by: login, registration, user create/update, settings save, test mail, reset. Use it for every new endpoint with sensitive input. Needs a secure context (HTTPS/localhost). No max password length (only a 4 MB body guard). New passwords are entered twice (`validatePasswordConfirm`, also checked server-side). Permissions are read from the DB on every request (`is_super`, `permissions` jsonb, `active`); IDs + labels live in `shared/admin.ts`. Super users implicitly have all permissions plus user management and the reset. The UI hides tabs/buttons via `can()`, but the server is the source of truth.
- **Encryption at rest of personal data** (`netlify/lib/pii.ts`): registration fields name, firstName, lastName, email, instagram, tiktok, referredBy, city are stored sealed (`sealRegistration` on write, `openRegistration(s)` on every read before returning/mailing/logging). Duplicate check via `email_hash` (`blindIndex`, HMAC). `encryptLegacyRegistrations` converts old plain rows (runs on admin list load). Audit `target`/`details` are sealed too (search filters after decryption); survey answers and Stripe/PayPal/SMTP secrets are sealed. Ticket tokens, payment refs and usernames stay plain (lookups).
- **Hardening**: security headers for the site in `netlify.toml` (strict CSP without inline scripts, HSTS, frame-ancestors none, nosniff, Permissions-Policy, COOP) and on every API response via `SECURITY_HEADERS` in `json()`. CSRF guard `isCrossSite()` (Origin / Sec-Fetch-Site) in `requireAdmin` and the public POST endpoints. Per-IP `rateLimit` in the function configs (login 20/min, registration 10/min, survey 30/min, payments 120/min, transport key 60/min, places 60/min). Per-account login lockout (`netlify/lib/login-guard.ts`, Blobs `login-attempts`, 5 failures/15 min → 15 min). `robots.txt` + `X-Robots-Tag` keep private pages out of search engines. New external origins (scripts, APIs) must be added to the CSP.
- **Audit log** (`netlify/lib/audit.ts`, table `audit_log`): `logAction()` never throws. Log every admin action (and new public registrations) with a `target` snapshot like `#0001 · Name`, since rows may be deleted. Action IDs/labels in `LOG_ACTIONS`. Kept 3 months.
- **Undo** (`netlify/lib/undo.ts`): undoable actions pass `undo: UndoData` (previous state / deleted rows) to `logAction`; the `undo` jsonb never leaves the server (list only gets `undoable`, `undoneAt`, `undoneBy`). `undoLogEntry` claims the entry and restores in one transaction, checks the kind's permission, refuses on conflicts (newer revision, reused number/username, last super user) and logs `aktion_rueckgaengig`. Kinds: status (optional mail via `notify`), deleted registration, reset (all rows), check-in, user created/changed/deleted, settings. When adding a new undoable action, add a kind there.
- **Database**: Netlify Database + Drizzle (`drizzle-orm@beta`, `drizzle-kit@beta`). Schema `db/schema.ts`, client `db/index.ts`, migrations in `netlify/database/migrations/` (generated with `npx drizzle-kit generate --name ...`; never hand-edit or apply manually).
- **Shared** (`shared/registration.ts`): categories, statuses and validation used by BOTH browser and functions – change validation here only.

## Key directories
- `src/components/` – reusable UI (Button, TextField, Stepper, CategoryCard, Modal, Alert…)
- `src/components/admin/` – dashboard pieces (StatsOverview, RegistrationList, RegistrationDetail, ConfirmDialog)
- `src/pages/` – route components
- `src/lib/api.ts` – typed fetch client; throws `ApiError` (status + fieldErrors)
- `netlify/lib/` – server helpers (http responses, auth)

## Conventions
- All user-facing copy is German.
- Styling is plain CSS in `src/styles.css` using CSS custom properties (`--bg: #020203` = exact logo background; dark palette, purple gradient `--gradient`, glow `--glow`). Display font Syne, body Inter.
- Function imports use `.js` extensions for TS files (e.g. `../../db/index.js`).
- Category/status IDs are ASCII slugs (`kuenstler`, `bestaetigt`); labels come from `shared/registration.ts`.

## Non-obvious decisions
- Dashboard filtering/sorting/stats are client-side (fetches all rows); fine for event-scale data.
- Live updates: dashboard polls every 15s while visible, plus a `BroadcastChannel` ping from the registration page in the same browser.
- Registration draft is kept in `sessionStorage` so a reload doesn't lose input.
- CSV export uses `;` separator + BOM (German Excel) and neutralises formula injection.
- Registration fields: Vorname, Nachname, Künstlername/Stagename (stored in `name`, used everywhere as display name), E-Mail, Instagram/TikTok (URL or handle accepted, stored as bare handle without `@`; build links with `instagramUrl`/`tiktokUrl`), `referred_by`, `city`. New columns are nullable for old rows.
- Registration number (`#0001`) is the serial `id` formatted via `formatRegistrationNumber` – not a separate column.
- Landing: `Hero` (centered logo from `public/logo-*.webp`, `mix-blend-mode: lighten` because the logo sits on pure black) → CTA "Zur Anmeldung" revealed on scroll (`useReveal`) → form mounts on click with staggered CSS animations. A saved draft opens the form directly.
- Dashboard overview: stacked status bar + clickable tiles; "angenommen" is a filter group (kostenlos + zahlung_angefordert + bezahlt) via `matchesStatus`, not a stored status. Rows get a status-coloured left border (`status-bar-<status>`).
- Countdown (`src/components/Countdown.tsx`) under the hero logo: logo look (white Anton digits, no background), Tage/Std/Min/Sek labels only, counts down to event date + time in Europe/Berlin (00:00 if no time).
- Status mails use editable templates (`shared/mail-template.ts`, column `event_settings.mail_templates`): subject/title/body per status incl. `eingegangen` (confirmation after registration, toggle `sendConfirmation`), block order ("Baukasten"), design. Rendered identically on server and in the settings preview.
- Final statuses (`isFinalStatus`: kostenlos, bezahlt, abgelehnt) and pending online payments lock all status buttons (UI + server); fixes only via log undo.
- Online payment (`netlify/lib/payments.ts`): setting `paymentProvider` = link | stripe | paypal. With Stripe/PayPal the mail links to `/zahlung?ref=<paymentRef>` (`PaymentPage`), which creates a fresh checkout per click and polls `/api/payments/status`; the server verifies with the provider (amount, currency, registration id) and sets `bezahlt` + sends the ticket. `payments-reconcile` (every 10 min) catches closed pages. Credentials: settings (Einstellungen → Zahlung: Stripe secret key, PayPal client id/secret/mode – secrets sealed, never returned, `secretsSet` flags, "Verbindung testen" → `/api/admin/settings/test-payment`) with env fallback `STRIPE_SECRET_KEY`, `PAYPAL_CLIENT_ID`/`PAYPAL_CLIENT_SECRET`/`PAYPAL_MODE`; use `paymentCredentials()`.
- Mail templates also have image blocks `bild1–3` + `design.logoImage` (uploaded images) and a `umfrage` template (survey button via `surveyUrl`, placeholder `{umfragelink}`).
- Survey (`shared/survey.ts`, `event_settings.survey` + `survey_sent_at`, table `survey_responses` with sealed answers, `registrations.survey_token`/`survey_sent_at`): builder in Einstellungen → Umfrage, public page `/umfrage?t=`, results tab „Umfrage“. Changing `sendAt` re-arms sending; per-guest `survey_sent_at` prevents duplicates.
- Checkout (`/zahlung`, `PaymentPage`): cart with the configured product (`event_settings.product`, `shared/product.ts`: name, description, image (upload id or https URL), included VAT → net/VAT split), price = requested `amount_cents`. Setting `paymentProvider` may be `online` (= payer picks any configured provider; `allowedProviders()`); `startCheckout(row, origin, provider)` stores the chosen provider. Page blocks with a loading screen until `reconcilePayment` confirms.
- Payment flow: requesting a payment (`zahlung_angefordert`, label „Zahlung ausstehend“) always mails the checkout link (`/zahlung?ref=`); the old `link` mode is mapped to `online`. „Bezahlt“ is never set manually (PATCH rejects it) – only `reconcilePayment` after Stripe/PayPal verification. While pending, `POST /api/admin/registrations/:id/reminder` sends template `zahlungserinnerung` (button in `StatusActions`).
- Dashboard menu „Warenkorb“ (`CartSettings`, permission `einstellungen`): product config + preview + „Checkout testen“.
- Test purchases ("🧪 Warenkorb testen", `POST /api/admin/settings/test-checkout`, `netlify/lib/test-checkout.ts`): stored in Blobs store `test-checkouts` (24 h), same flow via `createProviderCheckout`/`verifyProviderCheckout` (reference `test-…`), provider `simulation` without keys; no registration, ticket or mail. `/api/payments/*` falls back to them when no registration has the ref.
- Log everything that changes the site: structured settings are diffed in detail (`netlify/lib/diff.ts`), plus payment starts/tests, test purchases, legacy encryption and log cleanup.
- Images in mails are attached inline (`netlify/lib/inline-images.ts`: default logo bundled in `logo-email.ts`, uploads from Blobs, external https URLs fetched at send time) – never rely on mail clients loading URLs from the (password-protected) site.
- Survey links are one-time: submitting burns `registrations.survey_token` and stores the answer in one transaction. „Reset für nächstes Event“ also deletes `survey_responses` and clears `survey_sent_at` (restorable via undo).
- UI: dashboard main menu collapsible (`menu-open` in localStorage); settings groups use `<Fold>` (`src/components/Fold.tsx`, native details, state per title).
- Check-in only lists ticket holders (kostenlos/bezahlt); stat „Eingecheckt X/Y“.
- Never log raw DB errors (they contain bound params incl. secrets/PII) – use `logError` from `netlify/lib/http.ts`.
- Mail (`netlify/lib/mail.ts` `sendMail`): own SMTP mailbox (nodemailer, settings `smtp*`) when configured, otherwise Resend (`RESEND_API_KEY`).
- All amounts are NET prices: show them with `formatNet()` („… € zzgl. Steuern“, `NET_NOTE`). The checkout adds the product VAT on top (`priceBreakdown(net, vat)` → gross); the gross charged is stored in `registrations.payment_amount_cents` (test purchases: `chargeCents`) and verified against.
- Home page welcome block (`Welcome` in `RegisterPage`): image (`event_settings.welcome_image`, mail-images id) left, text flush left (`welcome_text`, default `DEFAULT_WELCOME_TEXT`, `{ticketpreis}` placeholder, first line = heading) above the „Zur Anmeldung“ button; configured in Einstellungen → Veranstaltung → Startseite.
- `ticketPrice` setting (stored normalized, e.g. `15` / `12,50`) prefills the amount in `StatusActions`.
- Status emojis come from `STATUSES[].icon` / `statusIcon()` (dashboard only – `statusLabel` stays emoji-free because it's used in e-mails).
- Admin status workflow: `ausstehend` (default, orange) → `kostenlos` | `zahlung_angefordert` (with `amount_cents`) → `bezahlt` | `abgelehnt`. Buttons live in `StatusActions`; status colours are `--st-<status>` CSS vars. Legacy `eingegangen`/`bestaetigt` were migrated to `ausstehend`.
- Registration flow: Kategorie → Daten → Überprüfen (orange media-consent checkbox, required; server rejects without `mediaConsent: true` and stores `media_consent_at`) → Bestätigung.
- Event name/date/location come only from `event_settings` via `EventProvider` (`useEvent`, `EventMeta`, `EventName`) – never hard-code them. Pages poll `/api/event` every 15s and on focus; saving settings calls `announceEventChange()` (BroadcastChannel) for instant updates.
